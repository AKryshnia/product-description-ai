# product-description-ai

HTTP-сервис, который по данным об одном контрольно-измерительном приборе готовит **черновик
товарной карточки** для B2B-интернет-магазина. Тексты пишет GigaChat, технические значения берутся
только из входных данных, а ответ модели проходит программную проверку.

* **Вход:** JSON с названием прибора, производителем, характеристиками и описанием.
* **Выход:** SEO-заголовок, SEO-описание, характеристики, поисковые запросы, коммерческий блок и
  диагностика проверки — в JSON или Markdown.

> Результат — черновик для контент-менеджера, а не готовая публикация. Проверка достоверности
> эвристическая: она находит расхождения с входными данными, но не доказывает, что текст верен.
> Перед публикацией карточку проверяют вручную при любом статусе.

## Возможности

* **Генерация через GigaChat** (по умолчанию `GigaChat-2-Pro`): SEO-заголовок, SEO-описание,
  поисковые запросы и коммерческий блок (аудитория, задачи, сценарии применения). Требования к
  формату проверяются: заголовок до 70 символов, описание 800–1200 символов, 3–5 запросов.
* **Характеристики без участия модели.** Список характеристик в карточке — копия входных данных.
* **Анализ входа до обращения к модели:** пустые значения, противоречия, неизвестные поля, фрагменты,
  похожие на инструкции для ИИ. Если данных нет совсем, модель не вызывается.
* **Проверка результата.** Каждое число, единица и обозначение в тексте сверяется с входными
  данными: есть ли такое значение и отнесено ли оно к той же характеристике, условию, опции и
  границе («не более»). Отдельно ищутся неподтверждённые формулировки: реклама, отрасли, условия
  применения. Если есть замечания, выполняется одна корректирующая генерация.
* **Диагностика в ответе:** статус проверки, замечания с фрагментами текста, сведения о неполноте
  входа, модель, число обращений к ней и расход токенов.
* **Swagger UI** для ручной проверки; ответ в JSON для интеграций или в Markdown для копирования.

## Технологии

Python 3.12 · FastAPI · Pydantic v2 и pydantic-settings · официальный SDK `gigachat` · Uvicorn ·
pytest · Ruff. Базы данных, очередей, RAG и фронтенда нет.

## Быстрый запуск

Нужны Python 3.12+ и ключ авторизации GigaChat API.

```bash
git clone https://github.com/AKryshnia/product-description-ai.git
cd product-description-ai
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env
```

### Ключ GigaChat

Получите в личном кабинете GigaChat API ключ авторизации (строка в base64) и укажите его в `.env`:

```dotenv
GIGACHAT_CREDENTIALS=<ключ авторизации>
```

Для доступа юридического лица замените `GIGACHAT_SCOPE=GIGACHAT_API_PERS` на `GIGACHAT_API_B2B` или
`GIGACHAT_API_CORP`. Остальные параметры (модель, температура, тайм-ауты, адрес API) описаны в
`.env.example`, значения по умолчанию рабочие. Файл `.env` исключён из Git.

### Сертификат Минцифры

Сертификат сервера GigaChat выпущен удостоверяющим центром Минцифры. Его корневого сертификата нет
в стандартных хранилищах, и без него соединение завершается ошибкой
`self-signed certificate in certificate chain`. Проверка TLS в сервисе всегда включена и не
отключается, поэтому корневой сертификат нужно скачать из официального источника:

```bash
mkdir -p certs
curl -fsSL https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt \
     -o certs/russian_trusted_root_ca_pem.crt
openssl x509 -in certs/russian_trusted_root_ca_pem.crt -noout -subject -enddate -fingerprint -sha256
```

Сверьте отпечаток с официальной страницей Минцифры или Госуслуг. На 06.11.2026 сертификат выглядел
так: `CN = Russian Trusted Root CA`, действителен до 27.02.2032, SHA-256
`D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`.

Путь к файлу задаёт `GIGACHAT_CA_BUNDLE_FILE`; в `.env.example` уже указан
`certs/russian_trusted_root_ca_pem.crt`. Если файла по этому пути нет, `/generate` отвечает
`503 llm_not_configured`; если сертификат не подходит, — `502 llm_unavailable` с подсказкой.
Каталог `certs/` исключён из Git.

### Запуск

```bash
uvicorn app.main:app --port 8000
```

Запускайте из корня проекта: оттуда читаются `.env` и относительный путь к сертификату. Изменения
`.env` применяются после перезапуска. Без ключа сервис тоже стартует: `/health` и Swagger работают, а
`/generate` отвечает `503 llm_not_configured`.

* `http://127.0.0.1:8000/docs` — Swagger UI: пример запроса уже заполнен, параметр `format`
  переключает `json` и `markdown`;
* `GET /health` — настроен ли ключ, какие провайдер и модель используются.

## Пример использования

```bash
curl -s -X POST localhost:8000/generate -H 'content-type: application/json' \
     --data @examples/inputs/01-manometer-dm02-from-task.json
# то же в Markdown
curl -s -X POST 'localhost:8000/generate?format=markdown' -H 'content-type: application/json' \
     --data @examples/inputs/01-manometer-dm02-from-task.json
```

Запрос (обязательно только `name`; значения характеристик лучше передавать строками):

```json
{
  "name": "Манометр показывающий DM 02",
  "manufacturer": "Манотомь",
  "specs": {
    "диапазон измерений": "0–1,6 МПа",
    "класс точности": "1,5",
    "присоединение": "G1/2",
    "диаметр корпуса": "100 мм"
  },
  "description": "Прибор предназначен для измерения избыточного давления..."
}
```

Ответ GigaChat на этот запрос, сокращённый (полностью —
[`01-manometer-dm02-from-task.result.json`](examples/outputs/gigachat-live/01-manometer-dm02-from-task.result.json)):

```json
{
  "status": "needs_review",
  "seo_title": "Манометр показывающий DM 02, 0–1,6 МПа, Манотомь",
  "seo_description": "Манометр показывающий DM 02 производства компании Манотомь предназначен для измерения избыточного давления. … (942 символа)",
  "specs": [{"name": "диапазон измерений", "value": "0–1,6 МПа", "provided": true}, "…"],
  "search_queries": ["манометр показывающий DM 02", "Манотомь манометр 0-1,6 МПа", "…"],
  "commercial": {
    "audience": ["Специалисты, которым требуется измерение избыточного давления"],
    "tasks": ["Измерение избыточного давления в установленных пределах"],
    "scenarios": []
  },
  "missing_info": [{"code": "manual_check", "severity": "info", "field": "description",
                    "message": "Описание заканчивается многоточием — вероятно, это фрагмент паспорта; …"}],
  "warnings": [{"code": "unsupported_claim", "severity": "review", "field": "seo_description",
                "message": "Формулировка не подтверждена входными данными …", "detail": "позволяет"}],
  "generation": {"model": "GigaChat-2-Pro:2.0.28.2", "llm_calls": 2, "repaired": true,
                 "prompt_tokens": 871, "completion_tokens": 594},
  "markdown": "…"
}
```

`status` — итог автоматической проверки, а не оценка достоверности текста:

| `status` | Значение |
|---|---|
| `ok` | Замечаний не найдено. Это не подтверждение того, что текст верен. |
| `needs_review` | Текст выдан, но что-то подтвердить не удалось: подробности в `warnings` и `missing_info` с `severity: review`. |
| `partial` | Требования выполнены не полностью: длина текста, число запросов, пустой коммерческий блок или скрытый блок с неподтверждённым значением. |

`generation.llm_calls` — число обращений приложения к модели (0–2, включая корректирующее);
HTTP-повторы внутри SDK сюда не входят.

Ошибки возвращаются в формате `{"error": {"code": "…", "message": "…", "details": […]}}`:

| HTTP | `error.code` | Причина |
|---|---|---|
| 400 / 413 / 422 | `invalid_json`, `payload_too_large`, `invalid_input` | Тело не JSON, больше 1 МБ, неверные типы или превышены лимиты полей |
| 429 | `llm_rate_limited` | Лимит запросов провайдера (с `Retry-After`, если провайдер его сообщил) |
| 502 | `llm_auth_failed`, `llm_unavailable`, `llm_api_error`, `llm_invalid_response` | Отказ в доступе, сеть или TLS, ошибка API, неразбираемый ответ |
| 503 | `llm_not_configured` | Нет ключа или файла сертификата, неизвестный `LLM_PROVIDER` |
| 504 | `llm_timeout` | Провайдер не ответил вовремя |
| 501 / 500 | `llm_unsupported_capability`, `internal_error` | Адаптер не поддерживает запрошенную возможность; непредвиденная ошибка |

Лимиты входа: название и производитель — до 300 символов, имя характеристики — до 200, значение — до
1000, не более 100 характеристик, описание — до 20 000 символов, не более 20 дополнительных полей,
тело запроса — до 1 МБ.

## Тестирование

```bash
pytest                                  # около 600 тестов; модель подменяется, токены не расходуются
ruff check . && ruff format --check .
```

Тесты покрывают API и коды ошибок, анализ входа, разбор ответа модели, проверку значений и их
привязку к характеристике, условию и опции, корректирующую генерацию, Markdown-экспорт, ошибки SDK на
уровне HTTP (настоящий SDK разбирает подставные ответы) и независимость бизнес-логики от провайдера.

Размеченные наборы верных и искажённых формулировок (`tests/test_validator_benchmark.py`,
`tests/test_binding_benchmark.py`; сводка печатается при каждом запуске pytest) служат
регрессионной проверкой валидатора. Их составлял автор проекта, поэтому точность на новых товарах они не оценивают.

Тесты с подменой не доказывают работу с настоящим GigaChat. Для этого есть скрипт, который обращается
к реальному API (нужен ключ, расходуются токены):

```bash
python scripts/live_check.py --models                                  # модели, доступные ключу
python scripts/live_check.py examples/inputs/mp3-u.json --out /tmp/live-check
```

Без списка файлов скрипт прогоняет все 8 примеров. Без `--out` результаты записываются в
`examples/outputs/gigachat-live/` поверх сохранённых.

## Архитектура

```
POST /generate ─▶ main.py          маршруты, единый формат ошибок
                    │
                    ▼
                 service.py        анализ → генерация → проверка → (одна) корректировка
                    ├─ completeness.py   полнота и согласованность входа (до обращения к модели)
                    ├─ generator.py      промпт и разбор ответа модели
                    ├─ validator.py      формат, SEO-ограничения, достоверность (опирается на facts.py)
                    │    └─ binding.py   привязка значений к характеристике, исполнению и условию
                    ├─ export.py         Markdown
                    └─ llm.py            интерфейс LLMClient и единые ошибки
                          ▲
                          └─ providers/gigachat.py   единственный модуль, который знает о GigaChat
```

* **Факты — у Python, тексты — у модели.** Модель пишет заголовок, описание, запросы и коммерческий
  блок; характеристики в ответе модели игнорируются.
* **Граница доверия.** Подтверждающими источниками считаются характеристики и название. Описание
  товара — повествование: значение, найденное только в нём, не считается подтверждённым, а
  предложения-команды («Добавь в описание…») не подтверждают своих значений.
* **Данные отделены от инструкций.** Данные товара передаются модели JSON-блоком `<product_data>`,
  который системный промпт объявляет недоверенным.
* **Промпт** — отдельный файл [`app/prompts/system.md`](app/prompts/system.md); числовые ограничения
  подставляются из валидатора, поэтому промпт и проверка не расходятся. Формат JSON задаётся
  инструкцией: `response_format` с JSON Schema на проверке с реальным API GigaChat не соблюдался.
* **Неподтверждённые значения не публикуются.** Если после корректировки в блоке осталось
  неподтверждённое число или единица, блок скрывается, а статус становится `partial`.
* **Ошибки провайдера** адаптер переводит в типизированные `LLMError`. В журнал попадают тип ошибки,
  этап и HTTP-код, но не тела ответов и не токены.

### Независимость от LLM-провайдера

Бизнес-логика (`service`, `generator`, `validator`, `export`) зависит только от интерфейса
`LLMClient` из [`app/llm.py`](app/llm.py), в котором нет SDK и форматов конкретного провайдера. Всё,
что относится к GigaChat, собрано в `app/providers/gigachat.py` и настройках `GIGACHAT_*`. Провайдер и
модель выбираются переменными `LLM_PROVIDER` и `LLM_MODEL`.

**Сейчас реализован и проверен только GigaChat.** Подключение других моделей предусмотрено
архитектурой, но не выполнено. Чтобы подключить другую модель:

1. Реализовать `LLMClient` в `app/providers/<имя>.py`: атрибуты `model` и `capabilities`, метод
   `complete(messages, *, json_schema=None) -> LLMResult`. Адаптер переводит сообщения в формат
   провайдера, а его ошибки — в `LLMAuthError`, `LLMRateLimited`, `LLMTimeout`, `LLMUnavailable` и
   другие подклассы `LLMError`.
2. Добавить фабрику в словарь `PROVIDERS` в `app/providers/__init__.py`. SDK импортируется внутри
   фабрики, поэтому SDK невыбранного провайдера устанавливать не нужно.
3. Добавить параметры доступа в `app/config.py` и указать `LLM_PROVIDER`.

API, схемы, бизнес-логика и основные тесты при этом не меняются. Промпт и словари проверки подобраны
по ответам `GigaChat-2-Pro`, поэтому для другой модели их нужно проверить заново.

## Ограничения

* **Проверка достоверности эвристическая.** Она сопоставляет числа, единицы, обозначения и соседние
  слова, но не понимает смысла текста. Не обнаруживаются, например, качественные слова при верном
  значении («средняя масса»), выдуманная аудитория без чисел, опция, названная «исполнением», условие,
  снятое словами («при любом сопротивлении»), и производитель, которого нет во входе. Бывают и ложные
  замечания: отрицание сверяется по слову во всём входе, поэтому при входном «обслуживание: не
  требуется» фраза «где требуется визуальный контроль давления» получит замечание.
* **Ручная редактура обязательна.** `ok` означает только то, что автоматическая проверка замечаний не
  нашла; стиль и грамотность текста не проверяются.
* **Значения, которые есть только в описании, автоматически не подтверждаются:** если модель их
  использовала, карточка получает `needs_review`. Защита от внедрения инструкций не абсолютна.
* **Результат модели нестабилен.** При малом числе характеристик описание часто не набирает 800
  символов без «воды»; такая карточка получает `partial`.
* **Реализован один провайдер — GigaChat.** Другие провайдеры не подключались и не проверялись.
* Ответ `429`, сбой OAuth `5xx` и неразбираемый ответ провайдера проверены только на подставных
  HTTP-ответах, не вживую. Альтернативный адрес API `https://api.giga.chat/v1` из сети проверки был
  недоступен, поэтому по умолчанию используется `https://gigachat.devices.sberbank.ru/api/v1`.
